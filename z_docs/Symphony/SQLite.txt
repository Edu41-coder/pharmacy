Voir toutes les tables :
php bin/console dbal:run-sql "SELECT name FROM sqlite_master WHERE type='table'"

Voir la structure de la table user 
php bin/console dbal:run-sql "PRAGMA table_info(user)"

Voir tous les utilisateurs 
php bin/console dbal:run-sql "SELECT * FROM user"

Vérifier que le schéma est valide :
php bin/console doctrine:schema:validate

Voir le nombre d'utilisateurs :
php bin/console dbal:run-sql "SELECT COUNT(*) FROM user"

Vérifier les rôles :
php bin/console dbal:run-sql "SELECT email, role FROM user"

Non, ce n'est pas grave. Il y a deux approches pour gérer la base de données :
Approche Doctrine (qui ne marche pas actuellement) :

php bin/console doctrine:schema:update --force

Cette approche utilise les annotations/attributs des entités pour générer le schéma.
Approche directe SQLite (celle qui marche) :

php bin/console app:init-database

Cette approche crée directement les tables avec SQL.
Les commandes Doctrine ne marchent probablement pas à cause :
Des problèmes de session dans SQLite
De la configuration de Doctrine avec SQLite
Des chemins de fichiers Windows
Mais ce n'est pas grave car :
Les tables sont créées correctement avec notre commande
Les entités Doctrine fonctionneront quand même avec ces tables
L'application fonctionnera normalement
