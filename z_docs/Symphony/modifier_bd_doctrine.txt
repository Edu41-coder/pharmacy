# Modification des rôles utilisateurs dans Doctrine

## 1. Modification manuelle dans la base de données
```sql
-- Dans phpMyAdmin, exécutez :
UPDATE user 
SET roles = '["ROLE_ADMIN"]' 
WHERE email IN ('admin1@example.com', 'admin2@example.com');
```

## 2. Création d'une migration pour documenter le changement
```bash
# Créer une nouvelle migration
php bin/console make:migration --name=UpdateUserRoles

# La migration sera créée dans migrations/
# Modifiez-la pour inclure vos changements :
```

## 3. Exemple de migration
```php
public function up(Schema $schema): void
{
    // Documentation des changements manuels
    $this->addSql("UPDATE user SET roles = '[\"ROLE_ADMIN\"]' WHERE email IN ('admin1@example.com', 'admin2@example.com')");
}

public function down(Schema $schema): void
{
    // Réversion des changements si nécessaire
    $this->addSql("UPDATE user SET roles = '[]' WHERE email IN ('admin1@example.com', 'admin2@example.com')");
}
```

## 4. Marquer la migration comme exécutée
```bash
# Puisque les changements sont déjà en base
php bin/console doctrine:migrations:version --add YYYYMMDDHHMMSS --no-interaction
```

## 5. Vérification
```bash
# Vérifier l'état des migrations
php bin/console doctrine:migrations:status

# Vérifier les rôles en base
php bin/console doctrine:query:sql "SELECT email, roles FROM user"
```


Ah, je comprends ! Pour synchroniser les changements manuels de phpMyAdmin avec Doctrine, voici la procédure :
Après vos modifications dans phpMyAdmin :
# Générer une migration basée sur les différences
php bin/console doctrine:migrations:diff

# OU plus spécifiquement
php bin/console doctrine:schema:update --dump-sql
Si vous voulez juste valider les changements :
# Marquer la base comme à jour
php bin/console doctrine:schema:update --force

# OU
php bin/console doctrine:migrations:sync-metadata-storage

Pour vérifier l'état :

# Vérifier si la base est synchronisée
php bin/console doctrine:schema:validate

Mais attention :
Cette méthode ne documentera pas les changements de données (comme les rôles)
Elle ne détecte que les changements de structure (colonnes, tables, etc.)
Les changements de valeurs doivent toujours être documentés manuellement
Pour les changements de données uniquement (comme les rôles), le mieux est de :
Faire vos changements dans phpMyAdmin
Exporter les données modifiées (SQL)
Créer une migration avec ce SQL
Voulez-vous que je vous montre comment exporter les données modifiées depuis phpMyAdmin ?

Voici comment exporter les changements de données depuis phpMyAdmin :
1. Dans phpMyAdmin :
Faites vos modifications de rôles
Sélectionnez la table user
Cliquez sur "Exporter"
Options à choisir :
Format : SQL
Tables : Seulement user
Options :
INSERT uniquement
"Ajouter DROP TABLE" : Non
"Ajouter IF NOT EXISTS" : Non

Créez une nouvelle migration :
# Créez une migration vide
php bin/console make:migration --name=UpdateUserRolesFromPhpMyAdmin


Modifiez la migration (exemple) :

public function up(Schema $schema): void
{
    // Copiez ici le SQL exporté de phpMyAdmin
    $this->addSql("UPDATE user SET roles = '[\"ROLE_ADMIN\"]' WHERE id = 1");
    $this->addSql("UPDATE user SET roles = '[\"ROLE_USER\"]' WHERE id = 2");
}

public function down(Schema $schema): void
{
    // Réversion si nécessaire
    $this->addSql("UPDATE user SET roles = '[]' WHERE id IN (1, 2)");
}

Marquez la migration comme exécutée :

# Notez le numéro de version de votre migration
php bin/console doctrine:migrations:version --add YYYYMMDDHHMMSS


façons differentes de faire migration
Oui, il y a des façons plus simples ! Voici les différentes options, de la plus simple à la plus complexe :
Option la plus simple - Commande directe :
# Exécuter une requête SQL directement
php bin/console doctrine:query:sql "UPDATE user SET roles = '[\"ROLE_ADMIN\"]' WHERE id = 1"


Option via les fixtures (bon pour le développement) :

namespace App\DataFixtures;

use App\Entity\User;
use Doctrine\Bundle\FixturesBundle\Fixture;
use Doctrine\Persistence\ObjectManager;

class UserFixtures extends Fixture
{
    public function load(ObjectManager $manager)
    {
        $user = $manager->getRepository(User::class)->find(1);
        $user->setRoles(['ROLE_ADMIN']);
        $manager->flush();
    }
}


Option via une commande personnalisée :

namespace App\Command;

use Symfony\Component\Console\Command\Command;
use Symfony\Component\Console\Input\InputInterface;
use Symfony\Component\Console\Output\OutputInterface;

class UpdateUserRolesCommand extends Command
{
    protected function execute(InputInterface $input, OutputInterface $output)
    {
        // Votre logique ici
        $this->entityManager->createQuery('UPDATE App\Entity\User u SET u.roles = :roles WHERE u.id = :id')
            ->setParameters(['roles' => ['ROLE_ADMIN'], 'id' => 1])
            ->execute();
        
        return Command::SUCCESS;
    }
}
